# 连续透明视频桌宠

V5.14 在原有WPF宿主中增加透明WebM视频播放。保留原来的聊天、任务、缩放、喂饭、潜水收起、安静与游戏模式，不安装第二套模型或Agent。

## 动作和形象

当前选取同一套蓝发鲸鱼娘女仆的14段连续动画，覆盖呼吸、哼歌、张望、慢走、提起、触摸反馈、挥手、伸懒腰、读写陪伴、白米饭、休息、哈欠与行礼。它们不是根据聊天实时生成的视频，也没有语音口型。读写日常只是陪伴动作，真实日记状态继续来自原后台。

常态动作尽量播放到片段边界再切换；触摸、提起、喂饭及实际任务可打断。摸头反馈在候选中轮换，避免紧接着重复。同一播放模式的静态预览与小头像也取自这套素材，不混用旧生成画风。解码失败停留在同一角色的预览图并提示，不反复重启失败的片段。

原视频为640×360、24帧/秒，选中片段统一使用中间360×360透明显示区域，脚底基准一致；排除了动作越出该区域的候选。提起动作仅循环悬空段，避免拎着时突然站回地面。高倍放大仍受原素材分辨率限制。

V5.15增加可选的60帧动作包，按约1.35倍节奏离线插帧：常规动作447帧、7.45秒，悬空段200帧、约3.33秒。它是同一套许可素材的补帧衍生，没有新增原创动作或改变角色形象；补帧无法恢复原片没有的细节，快速遮挡处仍可能出现插帧瑕疵。

## 准备

先关闭桌宠，再运行：

```powershell
runtime/python.exe -X utf8 tools/prepare_pet_video.py
```

需要支持`libvpx-vp9`透明解码的FFmpeg。工具优先复用本机已有组件，也可用`--ffmpeg "完整路径"`指定。它只准备动作，不启用桌宠；没有可用解码器时会说明原因。

新安装也可运行`tools/prepare_vpet.py --video`，同时构建宿主并准备动作。仅复制新的素材到旧版宿主不会启用视频播放，需要使用包含V5.14播放器的宿主。

动作位于`vpet/characters/dafeiyu-v1/video/`，有`pack.json`、`decoder.json`、视频、预览和许可说明。本机组件路径尽量相对主程序记录，整体迁移后可继续解析；外置自定义FFmpeg迁移后可能需重新指定。公开源码不附带视频和FFmpeg二进制，工具从固定上游版本下载所需资源。

### 可选：60帧、1.35倍节奏

先准备原始动作包，另行准备[RIFE ncnn Vulkan](https://github.com/nihui/rife-ncnn-vulkan)的可执行程序及`rife-v4.6`模型。在本机验证过的工具版本为`20221029`。新动作包必须写入新目录；工具需要可用的Vulkan设备，全部插帧在准备阶段执行。

```powershell
runtime/python.exe -X utf8 tools/prepare_pet_smooth.py --source vpet/characters/dafeiyu-v1/video --output work/smooth-pack --ffmpeg "FFmpeg完整路径" --rife "rife-ncnn-vulkan.exe完整路径" --model "rife-v4.6完整目录" --fps 60 --speed 1.35
```

工具在黑、白背景分别插帧后还原透明通道，保留循环端点并无损编码VP9；中间帧位于输出目录旁的`smooth-frames/`，占用空间明显大于最终动作包，验收后可删除。检查形象、透明边缘和循环后，关闭桌宠，将生成目录完整复制为`vpet/characters/dafeiyu-v1/video-smooth/`，并安装V5.15宿主。只在完整生成后才会写入`pack.json`。宿主有此目录时优先使用，否则继续播放原24帧动作包。移走`video-smooth`目录并重启桌宠即可回到原动作包。

参数支持48或60帧及0.8—2倍速度，需重新生成整套视频；运行时不做实时补帧或变速。工具保留上游素材与RIFE的许可说明，不分发模型及工具二进制。

## 播放与资源

FFmpeg单线程流式解码，通过有界缓冲更新WPF图片；不把所有视频解压成常驻帧，不逐帧调用聊天模型，也没有声音自动播放。V5.15在常态切换前可额外启动一个解码器等待首帧，切换后接管并停止旧进程；取消或中断会清理预加载。播放期间成对申请/释放1毫秒计时精度，可能增加低负载时的唤醒及耗电。减少动效使用同源静态图；隐藏、最小化、退出和游戏模式会停止全部解码，宿主意外退出时也通过Windows作业对象清理其子进程。

运行素材约9MB，具体以实际文件为准，不包含已有FFmpeg及开发环境。帧率、CPU和内存需要结合机器、动作与窗口状态实测，源码构建通过不等同于动画在目标机器上达到24帧/秒。

60帧衍生包约146.4MiB，另外保留原包。一次本机隐藏Windows桌面验收连续11秒交付660帧，宿主工作集约309MiB、活动解码器约22MiB；二者CPU合计约1.03%，按全部逻辑处理器归一化。测试包含前面的动作/窗口演练，工作集并非启动最低值；预加载时会短暂增加一个解码器。该结果说明帧已交付WPF，不能等同于实际显示器逐帧呈现，也不是其他机器的性能保证。运行时只做CPU解码和WPF呈现，不运行RIFE或新的聊天模型。
