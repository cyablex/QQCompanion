# 自主动态与草稿

自动评估最多每48小时一次，从上次评估或发送计时。没有值得分享的内容就跳过，可以连续多天不发，没有日更目标。完成画作、跨天和重启都不会刷新这个机会。

先判断是否有内容可写，再比较近期公开表达、审核具体趣味。普通摸头喂饭流水账、泛泛心情和旧梗换词不应凑成动态。文字本身有趣也可以，不强求科普或成果。模型判断有主观性，默认保留主人确认。

## 查看与确认

在控制台的“偏好设置 → 待发动态”查看正文与配图，选择批准或这条不发。配图保存独立快照，之后删除画册原图不会悄悄换掉已审的配图。点击刷新可查看实际发送状态。

QQ主号也可使用：

- `/待发动态` 或 `/动态草稿`：查看待发正文与编号；有配图时可到控制台核对。
- `/同意动态 编号`：批准该编号对应的原稿。
- `/拒绝动态 编号`：放弃待确认或已批准但尚未发送的草稿。
- `/发说说`：主动请求重新评估一次，可以跳过自动冷却；默认仍出草稿，不代替审批，不保证一定有可发内容。

查看草稿、同意动态、拒绝动态的斜杠可以省略；例如 `同意动态 abcde123`。动态与评论审批共用QQ、桌宠的确定入口，支持全角斜杠、空白、大写编号和常见句末标点。请单独发送审批命令；编号有误或夹带其他话时会说明，没有执行。

也可以自然地说“这条动态按原稿发吧”。模型只提出 `post.approve` / `post.reject`，程序核对真实主人、当前原话、已实际展示且未改动的原稿和有效期后保存批准；好友评论继续使用独立的 `comment` 任务。查不到对应草稿不会改成批准其他内容。审批任务的确认由程序生成，普通闲聊可独立回答。

有草稿时发送一次待确认提醒，不占主动聊天次数；没有草稿不催审批。一次只保留一条未处理草稿，72小时后过期，不自动补发。拒绝后继续遵守自动冷却。

## 发布与恢复

默认必须收到批准才会发布；控制台可关闭“动态发布前确认”，仍执行自动冷却和内容审核。关闭确认不会把已有待审草稿直接发出去。

暂停、夜间免打扰、关闭自主动态时不发送，已批准草稿等条件恢复后再处理；到期或分享授权撤销则取消。更换账号后不会看到或发送旧账号草稿。普通聊天中的“我会发”不表示已批准或已执行。

重连时会核对主人历史中的明确动态审批命令，即使当时已收到聊天回答也不会漏掉授权。只恢复有效期内已实际展示的原稿，整批先保存批准和后续拒绝再发布，不重放其他旧管理指令。自然语言在正常聊天中按结构化任务处理，离线补读只恢复明确审批命令。

好友可见范围、发送回执和正文读回沿用原规则。结果不明只显示待核对，不自动再次发送；可在空间核对实际内容。测试不使用真实QQ发送。
